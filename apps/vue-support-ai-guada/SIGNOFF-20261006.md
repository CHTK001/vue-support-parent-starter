## 2. 本轮修复（交付内容）

### 2.1 SSE 空帧（`workspace/events`）

- **症状**：`GET /workspace/events` 返回的 SSE 帧只剩空 `data:`（curl 实测 14 字节、
  两个空帧），事件体丢失。
- **根因**：`BinaryHttpMessageConverter`（spring-support-common-starter）在
  `mediaType=null` 时 `canWrite` 短路认领所有类型；`writeInternal` 在守护线程里
  没有 ThreadLocal `HttpServletRequest`，写出 0 字节。
- **修法**：`AiWorkspaceEventStreamService` 改为自序列化 —— `objectMapper.writeValueAsBytes(payload)`
  后 `.data(byte[])`，并构造注入 `ObjectMapper`；与既有
  `NginxMetricStreamRegistry#sendJson` 同口径。
- **验证**：`api-accept` SSE 段 4 项 PASS（收到真 `add` 事件 JSON 载荷、path 相对根、
  sessionId 原样回传、15s 心跳）。

### 2.2 Agents 包管理 404

- 恢复 10 文件移植；写操作 `@Permission("admin")`、读开放；`/import` 拆
  multipart/JSON 双映射；`resolveUserPackage` 防路径穿越；
  `publishAgentsRoot()` 回写 `nomifun.agents-root`。
- 市场端点实为 `/api/agents/packages/market/sources|search`。
- **验证**：`api-accept` agents 段 21 项 PASS；sweep `[Agents] 45 可点 / 0 异常`。

### 2.3 Bot 四个出口

  前端 `bot.api.ts` 由假实现改为真调用。

### 2.6 视觉管线配置区读写 404（`/capabilities/:pipeline`）

- **症状**：`/capabilities/ocr` 加载期出现 `404 GET /v2/global-settings/ocr`（全站 sweep 唯一 4xx），
  配置区一张表单项都不渲染，点「保存配置」同样打到不存在的路径 → **读与写双双失效**。
- **根因**：前端 `pipelineApi.config/updateConfig` 指向 `/v2/global-settings/{group}`，
  但后端 `/v2/global-settings` **只有无参的 `GET/PUT`**（单条记录接口）；按分组的真实出口是
  `GET/PUT /v2/settings/{group}`（`SettingsController`）。且该出口是**双层信封**
  `{code, data:{success, data:{field -> value}}}`，`javaApi.ts` 的客户端 `unwrap:false`，
  直接取 `res.data` 只会拿到内层信封。
- **修法**：
  - `javaApi.ts` 新增 `flattenGroupSettings()`，`pipelineApi.config/updateConfig` 与
    `settingsApi.globalBeans/updateGlobalBeans` 全部改指 `/settings/{group}` 并就地摊平，
    形状与 `settings.api.ts` 的 `fetchGroupSettings` 一致；
  - `CapabilityPage.vue` 新增 `configGroup` ref，取管线自述的 `configGroup`
    （如文生图管线 → `generate` 组，此前拿路由里的 pipeline code 当分组名，二次出错），
    并过滤 `__meta`（每项的 origin/overridden 归属信息，不是可编辑字段）。
- **验证**（浏览器 + 接口真值往返）：
  - `/capabilities/ocr` 配置区渲染出 **7 个字段** = API 返回 8 键 − `__meta`；日志中
    `/v2/global-settings/ocr` 最后一次 404 停在改动前的 `03:07:16`，此后再无该请求；
  - 点「保存配置」→ toast「配置保存成功」→ 接口读回 `sort_reading_order=false`（真写入生效）；
  - 随后按原值还原：`detector_model=""`、`sort_reading_order=true`、
    `device=cpu`、`detector_threshold=0.5`、三个 model 字段为空，与改动前完全一致。
