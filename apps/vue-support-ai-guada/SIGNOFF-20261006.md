### 2.9 生产级 sweep 实测出的缺陷：全站弹窗按 Esc 关不掉（`LDialog.vue`）

- **现象**：点开任意弹窗后直接按 `Esc`，弹窗纹丝不动。实测（dist 生产形态）：
  打开技能详情弹窗 → `activeElement` = `BODY` → `keyboard.press('Escape')`
  → 遮罩计数仍为 `3`，**没有关掉**。
- **根因**：`LDialog` 把 `@keydown.esc` 绑在 overlay 根节点上（模板 127 行），
  overlay 虽带 `tabindex="-1"` 但**从不主动获焦**。用户用鼠标点按钮打开弹窗后
  焦点仍停在 `body`，按键事件根本不经过 overlay，handler 收不到 —— Esc 天然无效。
  只有焦点恰好落在弹窗内部（Tab 进入、或点过弹窗内可聚焦元素）才关得掉。
- **影响面**：`<LDialog>` 被全站 **41 处**弹窗复用，等价于「全站弹窗 Esc 均不可用」。
- **修法（不碰 focus，避免回归）**：新增模块级 Esc 栈 + document 级监听，
  只在有弹窗打开期间存在、且**只关最上层**那个。
  - 之所以用栈而非每实例各监听一条 `document`：存在「弹窗里再开弹窗」，
    每实例都监听的话一次 Esc 会把整叠全关掉。
  - 焦点在最上层弹窗**内部**时必须让开（此时 overlay 自己的 `@keydown.esc` 已处理，
    document 监听随后也会收到冒泡，两边都执行就 `close()` 两遍 →
    `update:modelValue`/`close`/`closed` 重复 emit、定时器叠加）。
  - **刻意不做**「打开时聚焦 overlay」：会抢走弹窗内输入框由业务代码自行调用的 `focus()`，
    属行为回归；本仓 `src` 内 `autofocus` 用法为 0，但业务手动 focus 仍存在风险。
  - `onBeforeUnmount` 里摘登记项，避免组件被父级 `v-if` 直接卸载时栈里留死记录。
- **验证**：`probe-esc.cjs` 对 dist 生产形态 **3/3 PASS、0 pageError**：
  ① 焦点在 body 时按 Esc → 遮罩 `3→0`；② 焦点在 overlay 内时按 Esc → `3→0`（且不重复 close）；
  ③ 点 X 关闭按钮仍可用（回归）。

### 2.10 生产级 sweep 实测出的缺陷：出图媒体**同图重复派发 159×**（`authImage.ts`）

这条是 `sweep-final3` 上 **10 条 FAIL 的唯一根因**，也是本轮最重要的功能修复。

- **现象**：`/image-generate` 静置 15 秒（**一个按钮都不点**）：
  | 指标 | 修复前 | 修复后 |
  |---|---|---|
  | 总请求 | **3182** | **20** |
  | 不同地址 | 20 | 20 |
  | 平均重复倍数 | **159.1×** | **1.0×** |
  | 单地址最多请求 | **372 次** | **1 次** |
  | `net::ERR_INSUFFICIENT_RESOURCES` | **294** | **0** |
- **根因**：`authImage.ts` 的 `resolve(url)` 用 `settled.has(url)` 去重，但
  `settled.add(raw)` 写在 `load()` 的 `finally` 里 —— **要等 fetch 落地才标记**。
  而 `resolve()` 是模板里直接调用的（`ImageGeneratePage.mediaSrc(url)`），
  **每渲染一行就调一次**；地址未就绪期间页面只要重新渲染，`settled` 还是空的，
  于是再 `void load(url)` 一次，请求还没回来就又被复制。
- **为什么算 FAIL**：并发风暴打出 294 个 `ERR_INSUFFICIENT_RESOURCES`，
  被 harness 记进 `bucket.failed` → 命中元素的 `rec.err` →
  `ImageGenerate` **9 个按钮被判 `click-error` FAIL**，
  另有 1 个**已经成功跳转**（`urlChanged=true, afterUrl=/image-search`）的侧栏项
  「以图搜图」被同一串后台媒体失败拖成 FAIL。`clickErr` 全为 `null`
  —— 即**点击本身完全正常**，错在归因到的后台请求。
- **修法**：在 `resolve()` 里**派发前同步占位**（`settled.add(url)` 提到 `void load(url)` 之前）。
  语义与原意完全一致（一次地址只发一次、成功写 `blobUrls`、失败停在 `settled` 不重试 ——
  与 `load()` 内注释「避免渲染期疯狂重试」的原意相符），只是把「pending 窗口内重复派发」堵死。
  该工具被 `ImageGeneratePage` / `ImageSearchPage` / `ImageLibraryPanel` **三处共用**，一处修复全站生效。
- **验证**：`probe-media2.cjs` 同口径前后对照（上表）；`vue-tsc --noEmit` = **0 error**；
  修复随 `47c04fde` dist 重建后，`sweep-final4` 的 `[Chat]` 路由由
  `异常 1 -> 以图搜图(click-error)` 变为 **`异常 0`**。

### 2.12 覆盖面加强：50 个「无 accessible name」的可点控件原来根本没测

这条直接对应「**每个**可点按钮/图标都要测」—— 原判据在这 50 个上是空的。

- **原判据**：`if (!it.name) { rec.state='no-accessible-name'; warn++; continue; }`
  —— 采到了、也判定它可见可点，但**直接跳过不点**。
- **为什么这是真缺口**：这类元素在不少页面是该控件**唯一**的采集代表。
  `CLICKABLE_SEL` 只收 `button / [role="button"] / .el-button / .re-button / .rs-btn /
  a[href] / .el-dropdown-menu__item / [class*=icon-btn]` ——
  `label.el-switch` 和 `<input>` 都不在里面；`<input>` 也不在第二遍的
  `div,span,li,td,th,label,img,svg` 启发式里。于是：
  - **Element Plus 开关**只以内部 `span.el-switch__core` 被收进来（`extra:true`），
    又因为开关的表单文字在**兄弟节点**上、不在 core 的 `textContent` 里 → 无名 → 跳过；
  - **下拉/输入**只以 `div.el-input …cursor-pointer` 外层被收进来 → 同样跳过。
- **实测规模（`sweep-final4`）**：`no-accessible-name=50`

  `el-input…cursor-pointer` 36 个，全在 DefaultModels），**全部 `extra:true`、全部未点击**。
  同一分类下 Bots 的 `el-switch__core` 因旁边恰好有文字拿到 name、`state=ok` ——
  说明这类元素**点得动、也测得出来**，跳过纯属误伤。
- **改法（只加强不放松）**：删掉 `continue`，改为 `rec.noName = true` 后**照常走点击与分类**；
  无障碍观察改由 `summary.noAccessibleName` 按 `noName` 标记统计，并在汇总里**单独打印一行**
  （「可点但无 accessible name（已照常点击，仅无障碍观察，不计 FAIL）」），
  即 a11y 问题**不会因为点了它就被抹掉**，只是不再以「不测」来体现。
- **验证**：`SystemSettings` 单路由复验 —— 9 个 `el-switch__core` 全部进入
  「无可访问名的可点元素」清单 **且全部被点击**，其中一条 `effect`

**症状**：`platform=custom` 的 provider（如 `laguna-s-2.1` → `api.gavinchen.top`）
聊天流式恒返回 `finishReason:"error"`, `error:"All 1 client(s) stream failed"`。

**三层根因（逐层剥出）**：

1. **SPI 注册缺失**：`META-INF/extensions/com.chua.common.support.ai.chat.ChatClient`
   只注册了 `openai/siliconflow/sensetime/github/gitee/dots`，没有 `custom`。
   `ServiceProvider.getNewExtension("custom", …)` 落到 `DEFAULT_DEFINITION`
   （`implClass=null`），日志 `扩展实例化失败: name=custom args=1 原因=null`。
   *修法*：扩展文件追加 `custom=com.chua.openai.support.OpenAiChatClient`。

2. **首次部署写错位置**：把扩展文件与 class 放到 fat JAR **根目录**
   （`META-INF/extensions/…`、`com/chua/…/OpenAiChatClient.class`）——
   Spring Boot fat JAR 根目录**不在应用 classpath 上**（只有 `BOOT-INF/classes/`
   与 `BOOT-INF/lib/*.jar` 在），且根目录的 class 会被**系统类加载器**先捡到，
   因其依赖（`ChatClient` 接口在嵌套 JAR 里）不可见而抛
   `NoClassDefFoundError`，反而把 `BOOT-INF/classes/` 里正确文件的
   `readLine` 一并打断（`ReflectUtils.forName` 返回 null → NPE →
   **整个文件被 try-catch 弃读**，一个坏行废掉全文件）。
   *修法*：删除根目录两个文件；扩展文件同时落在**内层 JAR**（正确 classpath 位置）
   与 `BOOT-INF/classes/`（兜底），两处合并去重无害。

3. **`zip` 把嵌套 JAR 条目压成 Deflate —— Spring Boot 只认 STORED**：
   用 Info-ZIP 更新 fat JAR 里的嵌套 JAR 时，`zip` 默认 Deflate（`method=8`）
   + 24B extra field，而 fat JAR 内**其余 1456 条嵌套 JAR 全是 `method=0`（STORED）**
   —— Spring Boot 的 `NestedJarFile` 按 STORED 直读嵌套 JAR，遇到 Deflate 条目
   `getResources` **静默找不到该 JAR 内的任何资源**（openai-starter 的扩展文件
   与 class 从此对类加载器不可见，`classpath.idx` 里明明列着它）。
   *修法*：`fix-stored.py` 以 Python `zipfile` 全量重写 fat JAR，
   将 `BOOT-INF/lib/utils-support-openai-starter-4.0.0.42.jar` 一条改为
   `ZIP_STORED`（无压缩、无 extra），其余 1456 条原样拷贝；校验
   `compress_type=0` + `testzip()` 通过后原子替换。

**排障路径（给后来者）**：`getExtensions()` 缺项 → 开
`LOGGING_LEVEL_COM_CHUA_COMMON_SUPPORT_SPI=TRACE` drop-in →
`CustomServiceResolver` TRACE 逐 URL 打印「找到资源 / 读取配置行 / 处理异常」，
一眼看出「哪个 JAR 没被 `getResources` 找到」与「哪一行 readLine 抛了什么」。
TRACE 用完删 `13-spitrace.conf` + `daemon-reload`。

**验证**（2026-10-07，指纹 `5717cefd`）：

### 2.17 分块监督进程的一处**假换包**缺陷（会让整轮白跑，已修）

- **现象**：`run-sweep-chunks.ps1` 在 23:18:36 打出
  `!! jar md5 变了: FAAEeedeeecedcedecec (期望 5717cefd…) —— 换包即失效，禁止继续`
  并 `exit 4`，此时正跑到 16/25、前三个块 **PASS=1656 FAIL=0**。
- **不是真换包**：紧接着两次直连复核
  （`md5sum /opt/ai-starter/app.jar`）返回 `5717cefdd6a0880dbf4c25573513fb87`、`EXIT=0`，
  **包根本没变**，变的是那次 plink 调用的**输出**（网络抖动，压根不是 md5）。
- **根因**：取指纹用的是 `(($out -join '') -replace '[^0-9a-f]', '')` ——
  这个正则会**把任意文本里的十六进制字符全抠出来拼成一串**，
  于是错误输出被拼成 `FAAEeedeeecedcedecec`（20 位，连 32 位都不是），
  守卫拿它当 md5 比对，必然判定「变了」。**探测失败被误读成换包**。
- **危害**：抖动一次就作废整轮并退出；而且这类误判**不是**「换包即失效」想防的场景，
  反而会让重跑策略朝着错误方向走（把好数据丢掉）。
- **修法**：`Test-JarMd5` 改为只认 `\b[0-9a-fA-F]{32}\b` 的 token，
  取不到就返回 `PROBE_FAILED` 并把**原始输出**落日志；主循环里对 `PROBE_FAILED`
  **等 20 秒重跑本轮且不消耗轮次**（与 `root/api` 连通性守卫同一种处理），
  只有「确实取到 32 位 md5 且与期望不符」才 `exit 4`。
- **同时改掉的第二个坑**：`-ExpectDistMd5` 原来把历史值 `453f7131…` **写死成默认值**，
  dist 每重建一次就得改脚本，改漏就变成永远退 4 的死脚本。
  现改为**未指定就以起跑时的 dist 指纹为基线并锁定**（守卫真正要防的是
  「跑一半被别人重建」），显式指定则起跑时先核对、对不上直接作废。
- **代价**：这次误判损失了 round 4 的启动窗口，但已收下的 16/25 **分块完好**，
  重启监督进程后按缺哪些路由续跑即可（块号从 c04 接着编，不覆盖旧块）——
  这正是分块跑要达到的效果。

这是 §4 长期挂着的 open item，也是本轮 sweep 的 HTTP 台账里唯一一条**未定性为「正确响应」
的 4xx**（另一条 409 已定性为正确冲突）。本轮把它查穿并修掉。

#### 症状与根因：前端调了一个后端**从未实现**的路由

- 点「工作流配置」→ 弹窗正常打开（`弹窗4`），但「子Agent管理」页签的表格**永远空白**。
- 该页签 `loadSubAgents()` 调的是 `GET /api/agents/managed/{id}/sub-agents`。
  后端 `ApiAgentManageController` 对该路径**只有**
  `@PostMapping`(132) / `@PutMapping`(148) / `@DeleteMapping`(164)，
  **没有 `@GetMapping`** —— 路径存在但方法不匹配，Spring 对 GET 直接回 **405**。
- 只读探针实测（`probe-subagents-read.mjs`，带连通性自检 + 登录）：
  `legacy GET /{id}/sub-agents=` **405**；而同一主 Agent 的
  `GET /api/agents/managed/{id}` = **200 且自带 `sub_agents` 数组**
  （`SysAiAgentServiceImpl.listAgents:73` 与 `getAgent:81` 都是 `toResponse(agent, true)`，
  子表由 `subAgentsOf()` 按 `sort_order, created_at` 排序后塞进 `sub_agents`）。

#### 还有第二层：字段名两端各写一半，**只补 GET 也出不来数据**

| 位置 | 期望 | 后端实际 | 结果 |
|---|---|---|---|
| 表格列 | `id` / `order` / `condition` | `agent_id` / `sort_order` / **无 condition** | 三列全空 |
| 保存载荷 | `order` / `systemPrompt` | `sort_order` / `system_prompt`（`applyBody` 只认蛇形） | 顺序/提示词存不进去 |

即：即便把 GET 补上，表格仍然读不到 `id/order/condition`。
所以这条**不是「补一个接口」就能收工的**，必须同时定字段契约 —— 这正是此前
「未盲修」的原因。

#### 修法（**前端收敛到既有契约**，不动已部署的 jar）

契约不必新造：`GET /{id}` 已经在返回 `sub_agents`。因此让页面用**已存在**的详情端点：

1. `loadSubAgents()` 改调 `agentApi.get(id)`，取 `data.sub_agents`（刷新按钮同一条路径）；

4. 保存载荷按后端契约发 `sort_order` / `system_prompt`（原来发 `order` / `systemPrompt`）。
