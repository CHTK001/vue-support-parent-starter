## 1. 枚举方法与口径

清单**不是**靠源码正则扫出来的，而是运行时在浏览器里枚举「用户真的能点到」的元素。
判据与 `console-clickable-discovery.mjs` / `console-button-acceptance.mjs` **完全一致**：

- 可点击特征：原生 `button / a[href] / [role=button|tab|switch]`，或
  class 令牌命中 `btn$ / ^btn / icon-btn / ^el-button / ^rs-btn / (^|-)tab$ / tabs?$ / toggle / switch / (^|-)icon$`，
  或 `cursor: pointer`；
- **只取最外层**：祖先里有另一个可点击元素的不算（避免把按钮内部的 `<i>`/`<svg>` 图标重复计数）；
- 排除应用外壳（`.el-menu / .layout-tabs-bar / .layout-header / .el-aside` 等）与表格数据行；
- 右键菜单（`@contextmenu` 触发后才插入 `body`）静态枚举永远扫不到，**必须真实右键一次**。

枚举覆盖四个维度：**默认态**（刚进入控制台）、**激活表页签态**（点开一张表后）、
**四类右键菜单**（空白 / 库节点 / 表节点 / 页签）。

## 6. 无标签控件分析（枚举口径，非产品缺陷）

枚举出的「无标签」共 2 个（默认态），逐个核实后**都不是独立的用户控件**：

1. **`i.el-icon.el-select__caret`** —— 数据源下拉框的内部箭头图标。
   它是 `el-select` 组件的一部分，点击它等同于点开下拉框（`el-select` 整体可点）。
   枚举器按 class 令牌 `el-icon` 把它单独算进来，但它不是设计成独立可点击的控件。
2. **`i.el-icon.dbm-empty-icon`** —— 连接树为空时的装饰图标（`ReEmpty`），
   无 `@click`、无 `href`，本来就不可点。

**结论：JDBC 控制台不存在「纯图标且无名称的独立控件」**——所有真实控件都有文字标签或 `tip`/`aria-label`。

## 7. 验收判据（「必须生效」的定义）

对每个可点击控件，点击后必须出现以下**至少一种**可观测反应，否则判 FAIL（死按钮）：

1. 发出接口请求（`/ms/...`）；
2. 出现 toast 提示；
3. 弹出弹窗 / 下拉 / 确认框；
4. DOM 内容变化（列表、页签、树）；
5. URL 变化；
6. 元素自身及祖先的 class / `aria-expanded` / 可见性变化。

特殊规则：

- **破坏性控件**（删除 / 清空 / 停止 / 重置等，关键词 `删除|清空|移除|停止|关闭|断开|重置|销毁|drop|delete|clear|stop|reset|remove|destroy|truncate`）：
  弹出二次确认框即判生效，随后**取消**（绝不真执行），并用请求拦截挡住万一没有确认框时的真实写请求；
- **本来就禁用**的控件：不计为死按钮；
- **已选中态**（`active` / `is-active` / `checked`）：记 SKIP，不重复触发。

### 8.2 逐区域生效证据

**默认态（39 项，console-button-acceptance）**

- 根节点 / 库节点 → 展开/折叠切换（状态变化）；
- 30 个表/视图节点 → 逐个点击均真实发 `GET /ms/monitor/db/table/{name}/data` + `/columns`；
- 4 个对象分类节点（存储过程/函数/触发器/事件）→ 逐个点击均真实发 `GET /ms/monitor/db/objects/{type}`。

**激活表页签态（19 项，jdbc-active-state）**
- 统计总数（分段单选是/否）→ 切换后按新模式重载当前表（请求×3），分页器在「显示总行数 / 简易分页」间切换；
- 列显示设置 → 打开弹窗；
- 恢复默认设置 → 弹出二次确认框（破坏性操作的正确行为），随后取消，未执行；
- 表头显示模式「注释」→ 表头由 `id, name, score` 变为 `序号, 名称, 分数`；「字段+注释」→ `id（序号）, name（名称）, score（分数）`；

### 8.3 2 个 SKIP 的说明

均为**默认选中的子页签**（表头显示模式「字段」、行显示模式「数据」）：单选控件再点已选中项是无操作（正确行为，非死按钮），按判据记 SKIP。其余 2 个非默认项均已点击并验证生效。

### 8.4 归因

- **产品缺陷**：0。本次验收未发现死按钮、点了没反应、破坏性操作无二次确认等问题。
- **验收器/枚举器口径**（非产品缺陷，已在文档中标注）：
  - 枚举器把 `i.el-icon`（el-select 下拉箭头、ReEmpty 空态图标）计入可点击元素——前者是下拉框内部图标（点了等同点下拉框），后者无 `@click` 不可点。验收器已排除 `i.el-icon`，默认态 41 个枚举项中实际独立控件为 39 个；
  - 枚举器把 `span.dbm-subtab`（显示模式子页签）合并进其容器 `div.dbm-subtabs`（两者都命中 `tabs?$` 令牌，按「祖先优先」判据只留容器）。实际子页签是 5 个独立控件，已在激活态验收中逐个点击。
- **环境问题**：验收期间 8860 静态服务曾掉线 2 次（重启恢复）；浏览器一度报 `Target page, context or browser has been closed`（机器常驻多任务、内存紧张被挤掉），已通过 try/catch 兜底记 FAIL 而非崩溃——该轮重跑后通过，非产品问题。

### 8.5 验收用的判别性实验（证明「生效」而非推理）

- 表头显示模式：实地 dump 证实切换后表头 `TH.vxe-cell--title` 文本逐字变化（`id`→`序号`→`id（序号）`），不是靠「应该有变化」推断；
- 行显示模式：实地数 `.dbm-cell-comment` span 计数（0→5）；
- 分页：把页大小从默认 50 改为 20 制造出第 2 页，再点下一页/上一页，用请求×3 与页码文本变化双重证实翻页真实生效（默认 50 条/页时 25 行只有 1 页、下一页禁用，属正确行为而非死按钮）。
